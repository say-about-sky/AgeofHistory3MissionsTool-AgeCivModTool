1. 目录结构与加载机制

游戏使用 FileManager.loadFile() 按以下顺序查找文件：先遍历每个已启用 mod 目录的 external 路径，再遍历 internal 路径，最后回退 APK 内置资源。这意味着同路径文件自动覆盖。

模组根目录/（APK 内即 assets/ 下）
├── game/                              # 全局游戏数据（跨剧本共享）
│   ├── Civilizations.txt              # 文明 TAG 清单（分号分隔）
│   ├── civilizations/<tag>.json        # 文明定义（Tag / Name / iR / iG / iB / ReligionID / GroupID / Wiki）
│   ├── Governments.json               # 政体定义（change_ideology 的整数 = 条目顺序）
│   ├── NationalSpirit.json            # 民族精神
│   ├── Ages.json / Religions.json     # 时代 / 宗教
│   ├── buildings/Buildings.json       # 建筑（数组顺序 = 建筑 ID）
│   ├── diseases/Diseases.json         # 疾病（数组顺序 = 疾病 ID）
│   ├── characters/*.json              # 人物（add_general 系列的名字来源）
│   ├── rulers/<tag>.json              # 领袖（rulers/rulersImages/H 为领袖图）
│   ├── technologies/Technologies.json # 科技树
│   ├── units/Units.json + <兵种>.json   # 兵种索引与单文件
│   ├── advantages/Advantages.json     # 优势配置（advantagesImages/H 为图标）
│   ├── missions/                      # 全局国策树：Missions.json + missionsEvents/ + missionsImages/
│   ├── languages/                     # 翻译表（Bundle.properties / Bundle_cn_sp.properties …）
│   ├── gameValues/GV_*.json           # 游戏数值配置（另见《配置说明文档.md》）
│   └── events/ advisors/ generals/ settings/ ...  # 其余系统数据
├── gfx/                               # 图片资源（flagsXH 国旗 / ns 民族精神 / decision 事件图 / government 政体照片 …）
└── map/
    ├── Maps.json                      # 地图清单（Folder:）
    └── Earth3/                        # 一张地图（可有多个）
        ├── Scenarios.txt              # 本图剧本清单（分号分隔）
        ├── data/ProvinceDetails.json  # 省份 ID（单行 JSON，含 pid）
        ├── cities/cities.json         # 城市 / 省份名（Name + p）
        └── scenarios/TheGreatWar/     # 剧本（Data.json / descriptions/ / missions/ …，详见第 8 章）

2. JSON 配置格式约定

参考目录中的 JSON 文件并非严格 JSON。它们使用 Java/JS 风格语法，属性名不加双引号，且可能带有 # 行尾注释。游戏使用的 libGDX JsonReader 解析器有容错能力，能解析缺失逗号与注释。

// 参考文件中的实际写法（libGDX 可解析）
{
    Tag: "ynqin",
    Name: "大清",
    iR: 200,
    iG: 110,
    iB: 200,
    ReligionID: 27,
    GroupID: 1,
    Wiki: null
}

// 建议的安全写法（严格 JSON，也能被 libGDX 解析）
{
    "Tag": "ynqin",
    "Name": "大清",
    "iR": 200,
    "iG": 110,
    "iB": 200,
    "ReligionID": 27,
    "GroupID": 1,
    "Wiki": null
}
用标准 json.loads() 校验这些文件会报错；不要依赖普通 JSON 校验工具。可以用 libGDX 的 JsonReader 或 Python 的 json5 模块做预检。
重复键名会被解析器覆盖（后写覆盖前写）。示例中 MonthlyLegacy 出现两次，最终以最后一次值为准，容易引发逻辑 bug。
真实文件里还有更松散的写法，游戏解析器都能读取：缺逗号（Buildings.json 实验室条目）、数组尾逗号（MonthlyIncome: [0.3,]）、文件头 // 注释行（cities.json）。据此判断修改是否生效时，不要只看严格 JSON 校验工具的结果。

3. 文明 / 领袖 / 民族精神

3.1 文明索引（Civilizations.txt）

以分号 ; 分隔的 TAG 列表。只有在此注册的 TAG，游戏才会去加载 game/civilizations/<tag>.json。

ynqin;

3.2 文明定义（civilizations/<tag>.json）

{
"Tag": "ynqin",
"Name": "大清",
"iR": 200,
"iG": 110,
"iB": 200,
"ReligionID": 27,
"GroupID": 1,
"Wiki": null
}
字段说明
Tag文明唯一标识，需与文件名和 Civilizations.txt 注册保持一致
Name显示名称；优先级最高，若为中文直接采用
iR / iG / iB国家地图色 0–255
ReligionID宗教 ID，需在 Religions.json 注册
GroupID文明组/文化圈 ID
Wiki预留字段，通常为 null

3.3 领袖（rulers/<tag>.json）

{
	Rulers: [
		{
			Name: "沙耶",
			ImageID: 沙耶,
			
			BornDay: 11,
			BornMonth: 1,
			BornYear: 1900,
			
			ReignYear: 1910,
		},
	],
	
	Age_of_History: Rulers
}
字段说明
Rulers领袖数组，可定义多个
Name显示名称
ImageID领袖图片名（在 game/rulers/rulersImages/H/ 下）
BornDay / BornMonth / BornYear出生日期
ReignYear在位年份（从哪一年开始显示）
Age_of_History固定标记，值为 Rulers，不能省略

常见 Bonuses 键（参考目录出现过的）：

4.2 国策事件文件（.txt）

事件文件使用 key=value 行格式，分为三个区域：头部字段、触发器区块、选项区块。

id=专制主义
title=专制主义
desc=转变为专制主义

image=国策通用.png

show_in_missions=false
mission_image=tww.png
popUp=true
pobssible_to_run=true
no_background=true
focus_dura=35
no_text=true

only_once=true

trigger_and
next_and
has_variable_not=保守主义
has_variable_not=商业主义
has_variable_not=自由主义
civ_capital_unrest_over=-1
trigger_and_end

option_btn
name=
change_ideology=10
province_unrest_all=-99
ai=50
option_end

头部字段速查

字段说明
id事件唯一 ID（被 Missions.json 的 MissionEvent 引用）
title事件标题（弹窗显示）
desc事件描述文本（支持 § 颜色代码）
image事件弹窗图片
show_in_missions是否在国策树面板显示
mission_image国策树节点图片（放在 missionsImages/H/ 下）
popUp是否弹窗
possible_to_run是否显示为可执行；解析器实际键名（0.25.1 实测）。参考文件中的 pobssible_to_run 不会被读取
no_background是否去掉背景框
no_text是否隐藏文字
run_in_background是否后台执行（无 UI）
focus_dura国策执行天数
only_once是否只能执行一次
important重要事件标记
super_event超级事件标记
mission_desc国策树描述
exact_day精确触发日
拼写陷阱：参考目录的所有事件文件都写成 pobssible_to_run（多了个 b）。对 0.25.1 APK 的字符串表逐一比对后确认：解析器只含 possible_to_run 这一个相关常量，带 b 的写法不会被读取（等同没写此字段）；如需该字段真正生效，请使用 possible_to_run。

4.3 事件里的 ID / 名字从哪来（速查）

下列字段的取值对应游戏数据的「顺序编号」或名称，改动数据文件会改变编号含义：

取值数据文件编号规则详见
文明 tag（is_civ / annex_civ …）game/Civilizations.txt分号清单中注册的 tag 字符串§3.1 / §3.2
政体整数（change_ideology …）game/Governments.jsonGovernment: 数组条目顺序，从 0 起§4.4
建筑 ID（province_add_building …）game/buildings/Buildings.json建筑条目顺序，从 0 起§4.5
疾病 ID（province_id_spread_disease）game/diseases/Diseases.json疾病条目顺序，从 0 起§4.5
人物名（add_general 系列）game/characters/*.json文件内的 Name§4.6
省份 ID（province_*_id / CPID …）map/<地图>/data/ProvinceDetails.json各省份条目的 pid§8.2

4.5 建筑与疾病（buildings/ · diseases/）

建筑：province_add_building、province_id_build_add、province_has_building 等使用建筑 ID = buildings/Buildings.json 中条目的顺序（从 0 起）：

{
	Buildings:
	[
		{ Name: ["基础设施"], ... },                        # → 0
		{ Name: ["民用工厂"], ... },                        # → 1
		{ Name: ["铁路", "铁路Ⅱ", "铁路Ⅲ", "铁路Ⅳ"], ... },  # → 2（多级建筑：Name 数组即各级名称）
		...
	]
}

疾病：province_id_spread_disease 使用疾病 ID = diseases/Diseases.json 中条目的顺序；名称为英文键，中文名在根语言表（如 BlackDeath = 黑死病）：

{
	Disease:
	[
		{ Name: "BlackDeath", ... },   # → 0（黑死病）
		{ Name: "Smallpox", ... },     # → 1（天花）
		...
	]
}

4.6 人物（characters/）

add_general / add_general2 / add_advisor_character 等字段填写人物名，定义在 game/characters/*.json：

[
{
	Name: "gre乔治一世",
	ImageID: gre乔治一世,

	BornDay: 1, BornMonth: 3, BornYear: 1880,

	Attack: -1, Defense: -1,
},
]
编辑器同时收录 Name 与文件名作为候选（两者偶有不同）；填写时以文件内 Name 为准。

4.7 翻译表（languages/）

文明名在 languages/civilizations/Bundle.properties（默认）与 Bundle_cn_sp.properties（简中，优先）；其它名称（疾病等）用根语言表 languages/Bundle_cn_sp.properties。格式为 Java Properties：键 = 值，# / ! 开头为注释行，同键重复时后者覆盖。

5. 触发器（trigger_and … trigger_and_end）

触发器位于 trigger_and 和 trigger_and_end 之间。next_and / next_or 连接多个条件（AND / OR 组合）。

源码解析器还支持 trigger_or、trigger_and_not、trigger_or_not 等变体，以及 trigger_and_not_end 等结束标记。

参考目录中出现过的触发器键

键说明示例值
is_civ国家 ID（tag 字符串）ynqin
is_player是否为玩家控制true
is_not_player是否不为玩家true
civ_is_at_war是否处于战争中（空）
civ_is_not_at_war是否不处于战争（空）
has_variable变量是否存在变量名
has_variable_not变量是否不存在变量名
civ_gold_over金钱大于某值2800
civ_prestige_over威望大于某值20000
civ_capital_unrest_over首都动荡大于某值-1
province_controlled_by某省份由某国控制省份ID=国家tag

exists_any选项组中任意一个存在…

focus_dura国策执行时长（天）32

调试建议

  1. 改前先备份原始文件，改后重启游戏观察日志。
  2. 触发器/效果失效优先检查拼写，对照本文件的"源码支持键"列表。
  3. 用 MT 管理器打开 APK 内置同名文件对比字段差异。
  4. 图片缺失不崩溃但会显示 default.png，检查文件名大小写。
  5. _backup 目录不会被游戏读取，可以放心当版本存档。
