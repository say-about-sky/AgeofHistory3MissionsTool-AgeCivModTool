## Missions.json 国策树画布配置文件 
<details>
<summary>结构</summary>
*画布是按照行和列放置元素的*
*行和列都是正整数*
*从左向右是TreeColumn的正方向*
*从上到下是TreeRow的正方向*
*1正好对应400像素，所以一个单元格就能装下一个国策(小于国策照片：`ImageName`)*
<details>

<summary>Mission</summary>
<kbd>国策ID</kbd>  ID: 0,
<kbd>国策名称</kbd>  Name: "",	
<kbd>国策图片索引(`missionsImages`)</kbd>  ImageName: "(200x130).png",
<kbd>国策事件索引(`missionsEvents`)</kbd>  MissionEvent: ".txt",
<kbd>列</kbd>  TreeColumn: 0,
<kbd>行</kbd>  TreeRow: 0,
<kbd>前置国策</kbd>  RequiredMission: -1,
<kbd>额外前置国策</kbd>  RequiredMission2: -1,
<kbd>前置国策（列表写法，需全部完成）</kbd>  RequiredMissions: [2, 3, 4, 5],
<kbd>前置国策（列表写法，满足任一即可；可写 OR、OR2、OR3 三组）</kbd>  RequiredMissionsOR: [99, 101], RequiredMissionsOR2: [108, 110], RequiredMissionsOR3: [115, 116],
<kbd>互斥国策（不能与列表内的国策同时选择）</kbd>  MutuallyExclusiveMissions: [6, 10],
<kbd>AI选择概率(0~100)</kbd>  AI: 100,
</details>

> **工具的容错**：打开国策文件时会自动纠正常见写法问题——缺失的逗号、漏写的条目分隔符 `},` + `{`（表现为同一对象内重复 `ID`，会自动拆回两条）、缺省的基础字段（如 `AI` 按 100 读取）等；`RequiredMission` 系列与列表写法混用时会按原样保留，不会相互改写。
>
> **事件脚本的容错**：事件键位校验对模组实际写法保持宽容——空值合法；尾随 `=`（`2=`、`a=b=`、`3=0=…=0=`）合法；百分比/加成类字段可写小数（如 `bonus_duration=0.3`、`province_growth_rate=2.0`）；`省份列表;=数值`（如 `5220;2952;…;=15.0`）与 `文明A=文明B=数值` 均按实测语法识别；`dsec`（应为 `desc`）等常见拼写错误会在提示栏给出建议，但保存时原样保留。

### 代码示例
```
{

	Mission:
	[
		{
			ID: 0,
			Name: "",
			ImageName: ".png",
			
			MissionEvent: ".txt",
			
			TreeColumn: 0,
			TreeRow: 0,
			
			RequiredMission: -1,
			RequiredMission2: -1,
			
			AI: 100,
		},
	]
}
```
</details>

## missionsEvents 国策事件文件夹

国策事件文件定义了每个国策完成后的具体效果。每个国策对应一个`.txt`事件文件。

### 📄 事件基本结构
#### `必选项`必须要填，`可选项`不填也行，`可留空`指值可以不写(比如直接title=)
```
id=事件唯一标识 (通常与国策名相同) (必选项)
title=事件弹窗标题 (可留空) (必选项)
desc=事件描述文本 (可留空) (必选项)
mission_desc=国策详细描述文本 (可留空) (可选项)

image=*.png (国策显示照片) (可选项)
musicName=文本 (背景音乐名称) (可留空) (可选项)

show_in_missions=bool (是否在国策树界面显示) (可选项)
mission_image=*.png (国策完成照片) (可选项)
popUp=bool (完成时是否弹窗) (可选项)
pobssible_to_run=bool (是否可执行) (可选项) ⚠️笔误拼写：解析器实际读取 possible_to_run，本拼写不会被读取；新写或修正时请用正确拼写
no_background=bool (是否无背景) (可选项)
no_text=bool (是否不显示文本) (可选项)
run_in_background=bool (是否在后台运行) (可选项)
important=bool (是否重要) (可选项)
super_event=bool (是否为超级事件) (可选项)
focus_dura=整数 (国策执行所需时长/天) (可选项)

only_once=bool (是否只能执行一次) (可选项)

showCondition=文本 (显示条件表达式) (可留空) (可选项)
decisionCiv=整数 (决策文明ID) (可选项)
decisionDura=整数 (决策时长/天) (可选项)
execPosition=整数 (执行位置) (可选项)
layoutID=整数 (布局ID) (可选项)
preprocessorID=整数 (预处理器ID) (可选项)
runCivsID=整数 (运行文明ID) (可选项)

trigger_and
next_and
[触发条件]
trigger_and_end

option_btn
name=选项名称
[收益效果]
ai=整数 (AI选择该选项的概率) 
option_end
```

**逻辑操作符：**
- `next_and` - 与 (默认) 
- `next_or` - 或
- `next_and_not` - 与非

**逻辑块：**
- `trigger_and` ... `trigger_and_end` - 与条件块
- `trigger_and_not` ... `trigger_and_not_end` - 与非条件块
- `trigger_or` ... `trigger_or_end` - 或条件块

### ⚠️ 注意事项

1. **文件命名**：事件文件名必须与 `Missions.json` 中 `MissionEvent` 字段完全一致
2. **图片资源**：国策图片需放在 `missionsImages/H/` 目录下，尺寸建议 200x130 像素
3. **ID唯一性**：每个国策的 `ID` 必须唯一，`RequiredMission` 引用的ID必须存在
4. **条件语法**：`trigger_and` 和 `trigger_and_end` 必须成对出现，`trigger_or` 和 `trigger_or_end` 也必须成对出现
5. **收益语法**：`option_btn` 和 `option_end` 必须成对出现
6. **持续时间**：`bonus_duration=99` 表示永久生效，其他数值表示天数
7. **拼写注意**：`pobssible_to_run` 是参考目录里的历史笔误——0.25.1 APK 解析器字符串表中只有 `possible_to_run`（实测），带 b 的写法不会被读取；新写或修正该字段时请使用 `possible_to_run`
8. **值类型区分**：
   - **文本**：没有引号的字符串，用于变量名、标签名、事件ID等 (如 `has_variable=世界大战`) 
   - **字符串**：通常指带引号的字符串，但在此系统中大多使用文本格式
   - **文明ID**：一般是3-4个字母的标识符 (如atr、spa、fra、ger) 
9. **多值参数**：某些参数可以多次使用，如 `add_ns=` 可以添加多个国家精神
10. **复合值格式**：
    - `add_ruler=` 格式：`名=姓=全名=日=月=年` (如 `鲍里斯=三世=鲍里斯三世=30=1=1894`) 
    - `exact_day=` 格式：`日=月=年` (如 `15=8=1917`) 
    - `civ_is_vassal_of_civ=` 格式：`附属国=宗主国` (如 `bah=atr`) 
    - `declare_war2=` 格式：`宣战国=被宣战国` (如 `bra=ger`) 
    - `white_peace=` / `white_peace2=` 格式：`文明A=文明B` (如 `atr=ita`、`bul=tur_n`)；实测 4200+ 处多为 `==`（两段留空按上下文取默认方） 
    - `add_defensive_pact=` 格式：`国家1=国家2` (如 `fra=uni`) 
11. **取值来源**：省份 / 建筑 / 疾病 / 政体 / 人物等 ID 的来源文件与编号规则，见《游戏目录帮助文档.html》第 4、8 章；在编辑器中这些字段会直接给出候选与名称对照
