# 开发与维护指南

> 面向二次开发与问题排查，沉淀自 2026-10 对 GameCivs 五个模组的全量审计。
> 语法参考：[国策系统说明文档](国策系统说明文档.md) ｜ 数据文件总览：[游戏目录帮助文档](游戏目录帮助文档.html) ｜ 数值配置：[配置说明文档](配置说明文档.md)

## 1. 项目速览

- **用途**：编辑《文明时代 3》（Age of History 3）mod 的**国策树**与**国策事件脚本**；支持 Windows 桌面端与 Android。
- **技术栈**：[Dioxus 0.7](https://dioxuslabs.com)（前端，编译为 WebAssembly）+ [Tauri 2](https://tauri.app)（壳与原生能力）。
- **两个 crate**：

| crate | 路径 | 说明 |
|---|---|---|
| `age-civ-mod-tool-ui` | 根目录 `src/` | 前端 UI（wasm）；也被根目录 `cargo test` 直接使用 |
| `age_civ_mod_tool` | `src-tauri/` | 后端：文件 / APK / 签名 / 对照数据 / 命令层 |

## 2. 构建与运行

| 开发运行（桌面） | `cargo tauri dev`（或 `run.bat`） |

## 3. 模块地图

### 前端（`src/app/components/`）

| 文件 | 职责 |
|---|---|
| `mind.rs` | 国策树画布 / 拖动 / 连线 / 撤销；`MissionRecord` 镜像（**未知字段经 `serde(flatten)` 保留**）、保存时写出与 ID 重映射 |
| `event_parser.rs` | 事件脚本解析 / 序列化（逐字节保真模型；含 `round_trip_real_files` 全量回归） |
| `event_schema.rs` | 事件键位注册表：值语法校验、中文注释、`KNOWN_TYPOS` 拼写提示 |
| `event_grid.rs` | 事件表格编辑器（自绘候选下拉、触摸手势适配） |
| `event_lookup.rs` | 值 `=` 分段补全（文明 / 政体 / 省份 / 建筑 / 疾病 / 人物 / 精神 / 科技 / 宗教 / 资源 / 事件 / 音乐 / 图片）；省份列表段按 `;` 拆 token、按最后一个 token 过滤 |
| `files.rs` / `work.rs` | 资源管理器（含重命名、大文件操作进度卡）/ 工作区 / 标签页 / 撤销分区 |
| `tauri_bridge.rs` | Tauri invoke / 事件桥（`apk-progress` / `file-op-progress` / `workspace-changed`） |
| `undo.rs` | 三区（画布 / 事件 / 资源管理器）独立撤销 |

### 后端（`src-tauri/src/`）

| 文件 | 职责 |
|---|---|
| `apk_extract.rs` | 宽容解包（EOCD 异常、stored/deflate、ZIP64）；版块前缀**动态识别** |
| `apk_update.rs` | 版块导入 / 导出（追加数据 + 重建中央目录，不动原数据区） |
| `apk_pack.rs` | 整包重打（zip32、对齐、非 ASCII 置 UTF-8 flag） |
| `apk_signing.rs` / `bks.rs` | v1+v2+v3 签名 / BKS 密钥解析 |
| `mission_format.rs` | 国策文件宽松 JSON 纠正 + 规范序列化（**未知字段原样保留**） |
| `models.rs` | 前后端共享结构（`MissionRecord` 等；改字段需同步前端 `mind.rs`） |
| `commands/missions_db.rs` | 对照数据解析（含引号键 / 大小写宽容 / APK 兜底） |
| `commands/*` | 命令层：`apk` / `missions` / `events` / `icons` / `platform` / `scoped_storage` / `work_directory` / `workspace` / `workspace_watch` |
| `android_fs_bridge.rs` | Android SAF 桥（tree URI 规则见文件头注释，改动前必读） |
| `paths.rs` | 资源根推导（经典 `missions` / `assets/game/missions` / `assets/map/*/scenarios/*/missions`） |

### 测试矩阵

| 测试 | 端 | 覆盖 |

| `real_all_mods_lookup_via_apk_fallback` | 后端 ignored | **五个模组**的文明 / 政体 / 省份 / 人物 / 精神 + 自定义剧本根 |
| `discover_real_apk_section_prefixes` | 后端 ignored | 五个真实 APK 的版块前缀识别 |

### 加入新 APK 后的 5 分钟自检

1. **把新模组加进四处名单**（搜索现有模组名即可找到）：
   - `src/app/components/event_parser.rs` · `real_event_file_paths()` 的 `roots`
   - `src-tauri/src/apk_extract.rs` · `discover_real_apk_section_prefixes`（APK 路径 + 期望前缀）
   - `src-tauri/src/commands/missions_db.rs` · `real_all_mods_lookup_via_apk_fallback`（模组名 + 剧本根）
   - `src-tauri/src/mission_format.rs` · `real_modded_mission_trees_parse_and_round_trip`（目录列表）
2. **运行**：
   - 后端：`cargo test -p age_civ_mod_tool --lib -- --ignored --nocapture`
   - 前端：`cargo test -p age-civ-mod-tool-ui --lib -- --ignored --nocapture`
3. **解读**：
   - `round_trip_real_files` 报「文件数」与失败文件 → 事件解析兼容性
   - `schema_coverage_report` 看未知键 / 类型失败有没有**新面孔**（都是提示，不影响保存）
   - `real_all_mods_lookup…` 数量是否合理（例：road_to_56 无 `NationalSpirit.json`，精神=0 属正常）
   - `real_modded_mission_trees_…` 报错即指出具体文件；新字段已由 flatten 保留，不会丢

## 5. 兼容性与容错基线

### 当前保证（回归测试覆盖）

| 能力 | 保证 |
|---|---|
| 事件脚本打开 / 保存 | **逐字节一致**（含未知键、拼写错误、粘连行、CRLF、纯空白行；仅要求 UTF-8） |
| 国策树打开 | 宽松语法自动纠正（缺逗号、合并条目拆回、引号键、裸文本值、BOM）；列表写法前置 / 互斥；缺省字段兜底 |
| 国策树保存 | **未知字段原样保留**（`serde(flatten)`，保存后带回）；AI 权重不被改写；标量 / 列表写法互不改写 |
| APK 解包 / 导入导出 | ZIP64、EOCD 异常、任意地图 / 剧本目录名（动态前缀）；只替换版块、原数据区不动 |
| 对照数据 | 引号键（`"Name":`）、键名大小写（`name:`）、BOM、两种字段顺序；`Governments.json` 无 `Extra_Tag:` 条目不丢号；工作区缺数据时自动走**源 APK 兜底**（`.ageciv-source` 标记 / 顶层 APK / 「指定补全数据 APK」） |

### 边界（超出即降级 / 明确报错，不会损坏原文件）

| 边界 | 行为 |
|---|---|
| 非 UTF-8 文本（GBK/ANSI） | 打开报错（原文件不动） |
| 国策根键不叫 `Mission` / 字段类型不匹配 | 打开报错并提示 |
| 对照数据文件改名 / 换位置 / 键名大小写以外的新写法 | 对应补全列表为空（有提示条，功能降级） |
| 整包重打（apk.bat） | zip32 限制：≥65535 条目或 ≥4GiB 拒绝 |
| missions 不在 `assets/game/missions/` 也不在 `assets/map/*/scenarios/*/` | 版块导入不收录（如需支持先扩展 `section_prefix_of_entry`） |
| Android 版块导入 / 导出 | 需要「真实路径模式」；SAF 模式有引导提示 |

## 6. 排障手册（症状 → 根因 → 处理）

| 症状 | 根因 / 处理 |
|---|---|
| 打开国策报 `missing field RequiredMission` | 列表写法字段未识别（已修复；回归：`mission_file_supports_required_mission_lists`） |
| 打开国策报 `duplicate field ID` | 作者漏写 `},{` 合并条目（已自动拆分；`mission_file_splits_merged_entries…`） |
| 打开正常但「保存后游戏读不出」 | 检查是否在工具里保留了未知字段（已保证）；对比 `round_trip` 或备份 |
| 政体 / 省份等补全列表为空 | 数据文件缺失或改名；「从 apk 中导入」工作区会自动走源 APK 兜底，必要时用「文件 → 导入-导出 → 指定补全数据 APK」 |
| 版块导入后地图国策树没进来 | 原「白日升」类问题：地图 / 剧本目录名自定义；现已动态识别，重导一次即可 |
| Android 报 `Object.getClass() … null object reference` | SAF 目录操作缺 `documentTopTreeUri`（release R8 改写 `!!`）；改动一律经 `android_fs_bridge::root_uri` |
| Tauri 事件回调里 panic / `RefCell already borrowed` | dioxus 作用域规则：JS 事件回调**只允许 `Signal::set`**，重活放到 `use_effect` |
| 导出到 APK 失败 | 需真实路径模式；`content://` 先「复制到工作区后选中」 |
| 事件保存出现差异 | 理论上不会；先跑 `round_trip_real_files` 定位，再查 `event_parser` 模型字段 |
| 终端中文乱码 / 日志难读 | 用 `cmd /C "… > log 2>&1"` 写文件再以 UTF-8 读取（见第 2 节） |

## 7. 近期变更要点（2026-10 审计批次）

1. **事件脚本逐字节往返模型**：CRLF / 空白行保留、`next_` 衔接位置与别名、选项名位置、错配结束行、交错排版（`sequence`）——10156 个真实文件全部零差异。
2. **事件 schema 校准**：百分比字段接受小数、尾随 `=` 容错、`列表;=单值` Lambda、两批实测键注册、`KNOWN_TYPOS` 扩充、`lookup` 忽略键首尾空白；覆盖报告从「1781 类型失败 / 151 未知键」降到「14 / 41」，剩余均为模组自身异常。
3. **对照数据宽容**：引号键、键名大小写、`Governments.json` 无 `Extra_Tag` 兜底；新增 `real_all_mods_lookup_via_apk_fallback`。
4. **国策树**：列表写法前置 / 互斥、合并条目自动拆分、AI 权重保留、**未知字段保留**（前后端镜像 + 序列化）。
5. **APK**：版块前缀动态识别（修「白日升」）、ZIP64、桌面 / 安卓统一 File 句柄解压、胖包清理。
6. **文档归档**：全部说明文档移入 `docs/`，新增本指南与 [文档索引](README.md)。
7. **资源管理器文件操作（2026-10 本批次）**：复制 / 移动 / 删除命令全部改为 `async + spawn_blocking`（同步命令会阻塞主线程——大目录删除 / 粘贴卡顿的根因），`list_workspace_files` 加 `#[tauri::command(async)]`；新增 `file-op-progress` 事件（桌面按统计后的文件级进度、SAF 为不确定进度 + 已处理计数），前端右下角浮动进度卡展示；菜单新增「重命名」（同目录移动通道 + 撤销栈记录，标签页 / 事件面板路径跟随）。
8. **画布复制 / 粘贴（2026-10 本批次）**：右键国策「复制」（位于「删除」前）；**粘贴菜单随右键位置不同**——空白位置：「粘贴国策」/「粘贴国策+事件」；国策上：「粘贴国策」/「粘贴事件」。**「粘贴国策」= 只粘贴图标**：用剪贴板图标新建一张国策，标题按「来源标题+递增计数」命名（甲 → 甲0 → 甲1；编号避开现有国策标题与同名脚本），不复制 AI / 事件引用（不关联事件）；「粘贴国策+事件」在此基础上把来源脚本复制为带计数新文件（编号与标题对齐）；「粘贴事件」只把脚本副本应用到右键的那张国策（图标 / 标题不变）。计数命名：`事件脚本.txt → 事件脚本0.txt → 事件脚本1.txt`（取第一个未占用编号）。剪贴板携带图标数据，跨标签页粘贴可用。
9. **打包 / 导出前「未使用脚本副本」检查（2026-10 本批次）**：`打包 APK` 与 `导出到 APK` 动作前调用后端 `find_unused_event_scripts`，扫描 `missionsEvents` 中未被任何国策引用的 `.txt` 副本——「被引用」= 所在国策根 `*.json` 树的 `MissionEvent`（缺省时回退「标题.txt」），或脚本内 `run_event` / `run_event_instantly` 引用（保守扫描：行首匹配键且含 `=` 即整段记引用，宁可多算不误报）；脚本之间互相引用也计入。检测为**并行实现**（命令在 `spawn_blocking` 内执行，rayon 并行各模组根、根内国策树解析与脚本读取再并行）——实测 5 模组工作区（5000+ 脚本）全量扫描约 0.4~0.5s、单个大模组约 0.3~0.4s；扫描期间通过 `apk-progress` 事件上报**文件级进度**（复用 `ProgressEmitter`，前端加载面板显示进度条与「N / M 个文件」计数）。弹出对话框列出相对路径（**按「创建/修改时间」中较晚者倒序**——创建时间与修改时间哪个更晚按哪个排，最新的排最前；同一时间按路径升序；创建时间不支持的平台自动回退修改时间）；列表支持**逐项勾选**（点击行切换 ☐/☑），顶部有「全选/全不选」按钮与「已选 N / M 项」计数；列表为**虚拟滚动**（独立组件 `UnusedScriptsList`：行高 32px、只渲染可视窗口 ± 12 行缓冲、滚动按 2 行节流、行内最多两行省略号截断；勾选/滚动信号都在组件内读取，切换勾选不重渲染整个工作区）——上千条目（实测 1658 项）也能瞬时弹出。用户可选「删除」（只删除**选中项**，**未选择任何项时 = 全部删除**；单个失败不中断；**删除后不直接执行打包/导出**——若仍有未删除项则**停留在对话框**并刷新列表（失败项保留、勾选清空），状态栏提示已删除数量，可继续勾选删除或点「继续」；**全部删完**（列表为空）时自动关闭并继续打包/导出；删除进行中三个操作按钮禁用）、「继续」（不再删除剩余项，直接继续打包/导出）或「取消」（不删除、不执行本次打包/导出，仅关闭对话框）。打包只检查所选打包源目录子树；导出检查整个工作区。没有可解析国策树的根不判定（安全阀，避免尚未导入完整时误删）；导出时 SAF 路径模式跳过检查（导出本身需真实路径）。检查失败不阻断操作，仅在状态栏附注。
10. **APK 操作并行化提速（2026-10 本批次）**：①「打包 APK」（`apk_pack`）：文件收集改为**并行目录遍历 + 每条目单次 `symlink_metadata`**（同时得到类型与大小，取代原来两轮串行 stat）；压缩与写出改为**流水线**（rayon 工作线程压缩后续批次、经 `sync_channel` 传递，当前线程同步写出已完成批次，压缩与磁盘写入重叠）。②「导出到 APK」（`apk_update`）：新条目**并行读取 + 压缩**（`compress_source`，进度原子计数），随后顺序组装偏移/本地头/中央目录记录（数据零拷贝引用），整体改为 **1MB 缓冲批量写出**（数万条小记录原为逐条 write）。③「从 apk 中导入 / 解压」沿用既有自研并行解压器（zlib-rs + rayon + 单 File `read_at` + `openat` 父目录句柄缓存 + 安卓 `.nomedia`）。实测（Windows release，暮色黄昏0.25.1）：打包 11739 条/114.5MB **1.45s**；导出替换 11739 条到 1.3GB APK **1.89s**。评估过第三方方案：并行解压库（lzip-parallel/ripunzip 等）本质同为 rayon 并发、不优于现有解压器；`abxml` 类只解析特定条目；bsdiff 增量更新不适用本工具。忽略基准：`benchmark_pack_real_workspace` / `benchmark_update_real_apk`（`cargo test --release -p age_civ_mod_tool --lib benchmark_ -- --ignored --nocapture`）。
